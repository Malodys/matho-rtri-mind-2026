# 外部数据边界与审计规则

本项目的主训练集仍为赛题附件和已经审计的中间矩阵。外部来源只用于外部验证、元数据补充和方法讨论，不写入 `data/raw/`，也不改变主训练矩阵、切分或模型证据量。来源登记见 `external/source_manifest.csv`。

## 允许用途

- Kaggle Top Beer Information：在许可证、字段定义、单位和样本身份完成审计后，可用于风格、ABV、评分或描述信息的外部校验。不得把其评分直接当作消费者喜爱度标签，也不得与化学矩阵做未经确认的模糊连接。
- Zenodo `10653704`：与当前附件同源，用于基准复现和方法对照，不计作独立新增样本。
- Zenodo `21811627`：记录说明包含化学与感官数据，但文件受限，且 RateBeer 分数属于专有数据。项目不依赖下载权限，不抓取 RateBeer。
- Open Brewery DB 与 `beer.db`：仅用于酿酒厂、国家、风格、ABV 等元数据核对。它们不是化学测量或消费者标签来源。

## 匹配与可复现规则

1. 任何下载都必须在 manifest 中记录抓取时间、许可证、SHA256、行列数、字段说明、匹配规则和匹配/未匹配计数。
2. 只接受人工核验的精确身份匹配。默认禁止按名称相似度、模糊字符串或地理邻近关系把外部行并入主数据。
3. 外部数据不得覆盖赛题字段，不得用于训练、调参、补缺失或扩增样本。若未来需要训练扩增，必须另建数据版本、许可证审查和独立评估协议。
4. 合成样本、外部元数据和同源复现结果都不增加主证据量。跨实验平台的化学/感官结果只能放在讨论或外部验证中，并明确“候选机制需实验验证”。
